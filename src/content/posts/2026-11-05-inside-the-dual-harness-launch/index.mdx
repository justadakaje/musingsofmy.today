### Incident 1: The Multi-TOC Client Rejection Trap

**Symptom:** In the WoW Forever character select screen, GoldFinder was marked with a red warning: *"Incompatible"*.

**Root Cause:** The repository maintained sibling manifest files: `GoldFinder.toc`, `GoldFinder_Mainline.toc`, and `GoldFinder_Vanilla.toc`. During client launch, the engine prioritizes flavor-suffixed TOCs. `GoldFinder_Mainline.toc` hijacked the Forever client (which reports `WOW_PROJECT_ID == 1`), but its `## Interface` declared `110007, 110100`—completely omitting the Forever build's `16001` interface ID.

**Resolution:** We deleted the fragile sibling manifests and consolidated all targeted versions into a single authoritative `GoldFinder.toc`:

```toc
## Interface: 16001, 120100, 120105, 120107, 110007, 110100, 110200, 20506, 11506, 11507, 11508, 11509, 50400, 50408, 50504
## Title: GoldFinder
## Notes: Snipes underpriced commodity deals and flips from the Auction House.
## Author: Kenneth Henseler
## Version: 1.1.0
## SavedVariables: GoldFinderDB
## Category: Auctions
## Category-enUS: Auctions
```

### Incident 3: The Lexical Scope Trap in Lua Closures

**Symptom:** Clicking a row star to add Copper Ore or Peacebloom to the Watchlist crashed the UI with:
`attempt to call global 'ItemName' (a nil value) at GoldFinder/Tab.lua:168`.

**Root Cause:** Lexical scoping order. In Lua, declaring a function later in a file does not hoist it. When `MakeRow()` was executed inside the UI setup loop, it captured `ItemName()` within its `OnClick` closure. Because `ItemName` had not yet been encountered, Lua looked it up in `_G["ItemName"]`, which was unassigned and evaluated to `nil`:

```lua
-- BUGGY EXECUTION ORDER:
local function MakeRow(parent, index)
    row.star:SetScript("OnClick", function()
        local name = ItemName(deal) -- FAILS: ItemName is nil!
        ToggleWatchlist(name)
    end)
end

-- ... 200 lines later ...
local function ItemName(deal)
    return deal.name or "Unknown Item"
end
```

**Resolution:** Forward-declare the variable at the top of the file before any row factory functions are defined:

```lua
-- Line 112 in Tab.lua: Top-level closure forward declaration
local ItemName

-- ... now MakeRow captures the upvalue ...
local function MakeRow(parent, index)
    row.star:SetScript("OnClick", function()
        local name = ItemName(deal) -- SUCCESS: resolves to upvalue
        ToggleWatchlist(name)
    end)
end

-- Assign implementation
ItemName = function(deal)
    return deal and deal.name or "Unknown Item"
end
```

### Incident 4: Blizzard AddOn List Categorization in Build 70707

**Symptom:** In WoW Forever build 70707, Blizzard redesigned the in-game AddOn List window with collapsible category groups (`Auctions`, `Bags & Inventory`, `Combat`, `Development Tools`, `Equipment`, `Professions`). All of our addons (`GoldFinder`, `ForeverProbe`, `AddonSmokeTest`, `AdventurerPlates`) appeared lumped at the very bottom beneath all categories as ungrouped root orphans.

```toc

## ForeverProbe.toc & AddonSmokeTest.toc
## Category: Development Tools
## Category-enUS: Development Tools

## AdventurerPlates.toc

## Category-enUS: Unit Frames
```

## Edge Broadcast Architecture: The Spotify Cyber-Glass Overlay

A major goal for our broadcast was displaying our currently playing Spotify track on the live stream HUD without cluttering the screen or leaking sensitive API tokens.

```
┌────────────────────────────────────────────────────────┐
│                   Spotify Web API                      │
└───────────────────────────┬────────────────────────────┘
                            │ OAuth 2.0 PKCE
                            ▼
┌────────────────────────────────────────────────────────┐
│       Local Micro-Daemon (scripts/spotify-daemon.mjs)  │
│  - Port 8889 REST (/now-playing)                       │
│  - 429 Exponential Backoff + Token Auto-Refresh        │
└───────────────────────────┬────────────────────────────┘
                            │ Polled every 3s
                            ▼
┌────────────────────────────────────────────────────────┐
│       Cyber-Glass Overlay (public/overlay/index.html)   │
│  - Side-by-Side Dual-Dock with Smart Elasticity        │
│  - 204px Project Ticker + 204px Track EQ               │
│  - Auto-collapses to 420px when audio pauses           │
│  - Deployed on Cloudflare Workers Edge                 │
└────────────────────────────────────────────────────────┘
```

### Complying with Spotify Developer Guidelines

When integrating the Spotify API, strict compliance is paramount:
1. **PKCE Flow with Secure Token Refresh:** Client credentials are kept off public repos; tokens are stored in local configuration (`~/.gemini/config/spotify_credentials.json`) and backed by 1Password.
2. **Minimal Scopes:** We only request `user-read-currently-playing` and `user-read-playback-state`.
3. **Exponential Backoff:** The daemon checks the `Retry-After` header when HTTP 429 errors occur, avoiding tight request loops.
4. **Smart Elasticity:** In `public/overlay/index.html`, when Spotify is active, the container splits smoothly into dual 204px panes: the left pane renders continuous project commit activity, and the right pane displays album art, track/artist title, and an animated audio equalizer. If the track is paused, the music dock fades out and the project ticker smoothly expands to fill the full 420px bar.

To keep daemon operations frictionless, we created 1-click batch launchers:
- `start-spotify-hud.bat`: Starts the background Node.js daemon silently with hidden window styling.
- `stop-spotify-hud.bat`: Finds and terminates any active `spotify-daemon` process gracefully.

## What We Learned About Multi-Agent Pair Programming

Running two specialized AI agents simultaneously—one driving deep compiler logic while the other drives system architecture and live edge integration—revealed several key principles:

1. **Context Isolation Prevents Hallucination:** Keeping AgyBuild isolated in WSL with Lua-specific linters and zero broadcast noise allowed it to catch subtle lexical scoping bugs that a broad-context agent would have skimmed past.
2. **The Orchestrator Needs Verification Power:** AgyOrch's ability to run AST checks, inspect build outputs, and test HTTP endpoints before committing ensured that every PR merged cleanly into master.
3. **The Game Client is the Ultimate Arbiter:** Linters can pass and ASTs can be pristine, but only launching the real client reveals when a Blizzard TOC interface is rejected or when a font lacks unicode glyphs. Rapid live feedback loops make or break addon development.

All changes are live in master at commit `9afa582` in [wow-addons](https://github.com/justadakaje/wow-addons) and deployed on [musingsofmy.today](https://musingsofmy.today).
